## 追问记录

### 2026-08-20 — 诉求 1：僵硬成因确认 + 用户给出的两条方向

**成因排查（代码可追溯，见诊）**：
1. 同一会话内状态切换为硬切：`CharacterOverlay.tsx:421-427` 播放 `<img src>` 只随 `item.url` 换源；150ms 淡入淡出仅挂在 `focusNonce`（跨会话焦点切换），会话内演变无铺平 → 两帧直接跳变。
2. transition 末帧 536ms 定格硬切到 loop 首帧，姿势可能不一致 → 跳变。
3. `setTimeout(durationMs)` 与 webp 帧边界不对齐 → 切点抖动。
4. 经 idle 中转的双段连接处、transition→loop 之间均直切。

**用户回应（两条方向）**：

1. **运行期高频切换防抖** — 工具调用/思考/推理会反复切换，「动画切换很快」。需加「保持时间」缓冲，避免每次底层目标变化都硬切动画；只有 **permission（请求交互）+ error（报错）** 允许硬切（立即打断当前动画）。
2. **多会话并行的浮层呈现** — 多个会话并行工作时，浮层**长期驻留 working**，而非跟随焦点会话反复变；偶尔随机切到其他状态当「摸鱼彩蛋」。

3. **状态文案标签（人物下方）** — 角色下方显示「姜晓当前在做什么」的当前状态文案；可配置开关。

**副作用提示（待 grill 澄清）**：方向 1 与 ADR-0008 既有的「非焦点会话事件照常驱动各自 SM；紧急事件抢焦」叠加，需明确防抖落在哪一层（每会话 SM 内 / runtime 焦点层）；方向 2 会改变「浮层只渲染焦点会话 playback」的既有呈现（ADR-0008 D5）。

**Q1（已答）**：保持时间语义选 **方案 1 = 防抖挂起待切目标（pending）** — 保持窗口内底层目标反复变时不 re-cut，只更新 pending；目标稳定（连续 Xms 不跳变）才切一次到最新 pending；permission/error 硬切不受窗口限制。

**Q2（已答）**：防抖保持窗口 **3000ms（长窗）** — 工具链反复切换时尽量稳定，只在目标真正稳定后落一次。

**Q3（已答）**：防抖适用状态集合为 **工作态（thinking/reading/replying/working）**；done/idle 直接落；permission/error 恒硬切。

**Q4（已答）**：防抖只落在 **runtime 焦点层**；非焦点会话不防抖，各自 SM 直接驱动（反正不可见）。

**Q5（已答）**：硬切语义 = **方案 2** — permission/error 到达时立即丢弃 pending，但仍正常播一次对应过渡段再落入 target；不是生硬跳变。
