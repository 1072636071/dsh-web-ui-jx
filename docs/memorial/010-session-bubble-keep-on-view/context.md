## 事实查证（代码库，非问用户）

- **气泡消失的根源在 SDK 侧**：`SessionSummary.completed` 语义为
  "Finished while not selected and not yet opened — the sidebar's green 'done' reminder"
  （`dsh-client-runtime/lib/types/client/sessions/service.d.ts:49-50`）。
  一旦会话被打开（`sessions.open(id)`），该提醒位即被 SDK 清除，
  `buildBubbleGroups` 的范围过滤 `running || completed` 不再命中 → 气泡消失。
  「查看即消失」发生在 SDK 内部，客户端拦不住 → 「单击保留」必须由客户端
  本地记账（kept 集合）。
- **SDK 原生归档能力**：`IWorkspaces.archiveSession(sessionId): Promise<void>`
  （contract/workspaces.d.ts:89-94）：归档进 registry-global 集合，「hidden from
  grouping surfaces; session log and accounting slot remain」——从侧边栏等所有
  分组界面隐藏，日志保留。`WorkspaceListState.archivedSessionIds`（Host order）
  暴露归档集。⚠️ 归档当前会话会清空选择 → 视图跳 New Session state。
  ⚠️ 契约层无 unarchive / 恢复方法——归档单向，GUI 内不可逆。
- **真删除不存在**：`ISessions` 方法面、`IWorkspaces`、wire 层 `dsh-api-remotes`
  均无 session 删除 RPC；会话日志为 Host durable 数据，客户端无删除权限。
  插件可及的最重操作 = 归档。
- **插件边界**：本仓库 UI 面仅姜晓浮层 + 设置卡，无法给宿主侧边栏加入口；
  归档入口只能落在浮层上。
- 开关 UI 既有模式：`SettingsCard.tsx`「角色」section 已有 `role="switch"`
  toggle 与数字配置；配置模块模式见 `session-bubbles-config.ts`
  （localStorage + 轻量 store + useSyncExternalStore 订阅）。
- 整盒拖动排除机制：气泡挂 `data-jx-interactive`（ADR-0006/0007），
  气泡上的 pointerdown 不启动整盒拖动——气泡手势与整盒拖动天然分流。

## 追问记录

### Q1 — 单击/双击怎么区分（2026-02-14）

**问**：三方案对比——(1) 单击立即跳转+第二击移除（event.detail 判定，零延迟但移除时会先跳转）；(2) 双击窗口判定（~250ms 延迟，移除纯净但单击迟滞）；(3) 混合。
**答**：用户反提新方向——**改成拖动移除**；澄清为「拖动到一个区域，移除掉」（drag-to-target-zone）。
**小结**：拖动到区域方案使单击与移除彻底解耦：单击恒为「跳转+保留」，移除走独立手势，无双击判定延迟、无移除误跳转。Q1 的双击方案全部否决，转向拖动范式。

### Q2 — 移除区的形态与出现时机（2026-02-14）

**问**：三方案对比——(1) 拖动时才浮现临时目标区【推荐】；(2) 常驻小垃圾桶按钮（可发现性最好）；(3) 拖出即删无落点（歧义大、误删风险高）。
**答**：用户选 **(2) 常驻小垃圾桶按钮**。（后被 Q4 双投放区演化取代。）

### Q3 — 哪些气泡可以拖去垃圾桶（2026-02-14）

**问**：三方案对比——(1) 仅已完成类可拖（规避 running 复活问题 + pending 审批误删风险）【推荐】；(2) 全部可拖；(3) 仅已查看保留的可拖。
**答**：用户选 **(1)**，并提出**新增诉求：「还想做一个归档会话的功能，同样一起处理，两个配置」。**
**小结** → D3。

### Q4 — 垃圾桶语义 vs 真归档（2026-02-14）

**问**：(1) 垃圾桶=真归档【推荐】；(2) 仅本地隐藏；(3) 配置切换行为。
**答**：用户新提「弄两个区域接收会话气泡」——双投放区方案：**收起区**（本地
dismissed 集合，可逆）+ **归档区**（调 archiveSession，真归档不可逆）。手势即语义，
无需配置切换行为。
**小结** → D2。

### Q5 — 双投放区布局与误拖防护（2026-02-14）

**问**：(1) 远近分置+危险区警示【推荐】；(2) 双区并排；(3) 单区+Shift 修饰键升级。
**答**：用户选 **(1)**。**小结** → D4。

### Q6 —「两个配置」怎么切（2026-02-14）

**问**：逻辑洞先行——「①保留开关+②拖动手势开关」各自独立会出现①开②关时保留气泡无移除途径。三方案：(1) ①保留模式总开关+②归档区独立开关【推荐】；(2) 正交双开关+双击备胎；(3) 三独立开关。
**答**：用户选 **(1)**，并授权「其他你也全部自己决策」。
**小结** → D5/D6；其余开放点按授权自行决策（D7–D15）。

## 决策汇总

| # | 决策 | 状态 | ADR |
|---|------|------|-----|
| D1 | 单击保留的机制载体 = 本地 kept 集合：气泡点击跳转时记入集合，可见性过滤扩展为 `running \|\| completed \|\| kept.has(id)`；SDK 清除 completed 位不可拦截，故客户端记账直至显式移除 | 已定 | ADR-0022 |
| D2 | 移除交互 = 拖拽投放区（双击方案全部否决）；**双投放区**：「收起区」= 记入本地 dismissed 集合，可逆、不动 SDK；「归档区」= 调 `archiveSession` 真归档，气泡消失 + 侧边栏同步隐藏，不可逆 | 已定 | ADR-0022 |
| D3 | 可拖范围：仅 completed 类气泡（未查看 + 已保留均可）；running（复活问题）/ pending 组（审批误删风险）禁止拖动，视觉呈现禁止态 | 已定 | — |
| D4 | 布局与防护：「收起」区近放（气泡列正下方，高频轻操作）；「归档」区远放（角色脚边/浮层另一侧），警示视觉（琥珀/朱砂描边 + hover 提示「归档后从列表隐藏，不可恢复」）；距离即防误触栏 | 已定 | — |
| D5 | 配置①「会话气泡保留」总开关：关 = 完全回到现状（点击即跳转即消失，无拖动无投放区）；开 = 整套新范式（单击保留 + 拖动手势 + 收起区） | 已定 | — |
