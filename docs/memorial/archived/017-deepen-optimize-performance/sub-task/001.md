# 001 — 运行时性能候选点扫描

状态：已完成

## 任务描述

扫描 `d:/work/space/dsh-web-ui-jx`（DSH bundle 插件，host/client 双半区 + `packages/dsh-session-bubble` 库），找出**运行时性能**层面的可优化点，给出文件 + 行号证据。

## 明确问题

1. **client 渲染放大**：浮层/气泡列/详情弹框的重渲染路径。是否存在 `useSyncExternalStore` 快照引用不稳定（每次 getSnapshot 返回新对象/新数组）导致的无效重渲染？多个 store 订阅是否各自触发 setState 而非批量？定时器 tick 频率如何（`overlay-session-runtime` 的 tickIntervalMs 生产值）？
2. **动画/特效开销**：FX 系统（shimmer/fall/grain/warp）的实现方式，是否存在主线程布局抖动（非 transform/opacity 动画）、Web Animations API 实例泄漏、SVG filter（feDisplacementMap）重绘成本、`MutationObserver` 回调频率。
3. **内存与监听器**：`window`/`document` 级监听器、`setInterval`、`MutationObserver`、`ResizeObserver` 的注册与清理是否成对（ctx.effect / dispose）；localStorage `storage` 事件监听是否全局单例。
4. **网络与 host 半区**：`/api/dsh-jx/*` 路由是否有缓存/ETag/304；素材读取是否每次都走磁盘 `fs.readFile`；`sessionController.inspect` 是否有缓存与 in-flight 去重；AI 标题请求的节流与缓存策略。
5. **包体体积**：`lib/index.js` / `lib/client.js` 当前体积；`assets/`（35 webp + 2 woff2 + 2 png）总大小与单个最大文件；是否存在明显可压缩空间。

### 零、工单假设被证伪的三条（事实）

1. **「getSnapshot 每次返回新对象导致无效重渲染」不成立**——三处 store 均做了引用缓存：`overlay-session-runtime.ts:1412-1414`（只返回 `cachedSnapshot`，仅 `emit()` 重建 `:1092`）、`overlay-state-machine.ts:304-312`（注释明写「每次新建对象 → React error #301」）、`playback-cursor.ts:185-190`（惰性缓存 + `:141-146` 同引用二次守卫）。`CharacterOverlay.tsx:217-226`、`440` 三处 `useSyncExternalStore` 的 getSnapshot 全部稳定。
2. **「多个 store 各自 setState」不成立**——runtime/position/cursor 均走 `useSyncExternalStore.subscribe`（`:1416-1421`、`:192-197`），React 18 自动批处理。
3. **「feDisplacementMap 重绘成本」不存在**——`fx.css:117-118` 的 `feTurbulence` 是**静态** mask（`:119-120` 注释「静态：无 animation，零热循环」），全仓无 `feDisplacementMap`。

另有 5 项经核实**已正确实现**：监听器清理成对（`CharacterOverlay.tsx:299-301/326-329/337-339`、`fx/index.ts:213/232-236`、`warp.ts:237-238/250-257`、`welcome-backdrop.ts:427-437`、`SidebarEntry.tsx:122-126/139-141`、`SessionBubbleList.tsx:485-486`、`dynamic-title.ts:103/119-120`）；WAAPI 实例无泄漏（`fall.ts:137-146`、`warp.ts:143-145/262-273`）；`storage` 监听全局单例（`persistent-setting.ts:64-67`）；素材 ETag/304 已实现（`asset-routes.ts:92-101`）；AI 标题客户端节流+缓存已实现（`dynamic-title.ts:330-331` TTL 15min/节流 30s，`:273-292`）。

### 高影响

**H1 — 欢迎壁纸 MutationObserver 全域子树监听 → 强制同步布局风暴**
- 证据：`welcome-backdrop.ts:273` `observe(document.body, { childList: true, subtree: true })`；`:277-287` `handleSurfaceMutations` 无防抖、无 rAF 批处理、无深度/数量上限；`:166-172` `tagSurfaces` → `:154-162` `walkElements` 栈式全遍历；`:131-151` `isWallpaperSurface` 中 `:139` `getBoundingClientRect()` + `:142` `getComputedStyle()` + `:119-121` 长选择器 `closest()`。
- 事实：每个新增子树逐元素强制 layout flush + style recalc，同步执行于 MutationObserver 微任务内。
- 推断：流式输出场景回调次数与变更批次同量级，构成典型 layout thrashing（未实测）。
- 建议：① 回调改 `requestAnimationFrame` 合并 + 微批去重；② `isWallpaperSurface` 先用 `offsetHeight/clientHeight` 廉价前置过滤；③ 观察范围收窄到 `#root` 或加 depth 上限。
- 收益：高。风险：改变打标时机与覆盖面，需回归 ADR-0024/0027 视觉契约。

**H2 — assets 总体积 ≈ 187 MB，单文件最大 12.37 MB**
- 证据（实测体积）：35 webp ≈ 184.06 MB（34 角色 webp ≈ 183.82 MB + welcome 242.32 KB）；2 woff2 = 3.02 MB；2 png = 4.88 KB。合计 39 文件 ≈ 187.09 MB。最大：`assets/character/happy.webp` 12.37 MB，次大 surprised 8.54 / frown-wave 8.29 / error 8.22 MB。
- 事实：体积数据。推断：动图 webp 有可压缩空间、中文字体可子集化（**未实测**）。
- 建议：优先治理 >6 MB 的 13 个文件（合计 100 MB+）；字体子集化。
- 风险：触碰 ADR-0012 / ADR-0021 的既有资产口径。

**H3 — 素材路由 304 路径仍全量 readFile，且无压缩**
- 证据：`asset-routes.ts:91` `readFile` 位于 `:97` `if-none-match` 判定**之前**；`:102-106` 响应头无 `content-encoding`；全文件无内存缓存。
- 事实：每个请求（含 304）都付一次完整磁盘读 + Buffer 分配。
- 建议：① 先 `stat` 算 ETag，命中即 304 不读文件；② 按 `path+mtimeMs` 做 LRU 字节缓存。
- 风险：低，但**不可回退到强缓存**（`asset-routes.ts:87-90` 记录：曾用 `immutable, max-age=86400` 导致 24h 看不到新字节）。

**H4 — CharacterOverlay 重渲染放大到整个 SessionBubbleList**
- 证据：`CharacterOverlay.tsx:217-220` 订阅 runtime；`:563-568` 把 `<SessionBubbleList>` 渲染为子节点；`overlay-session-runtime.ts:1091-1095` `emit()` 无条件重建快照（调用点 14 处：`:482,589,653,679,690,735,763,827,837,1200,1293,1303,1326,1447`）；`SessionBubbleList.tsx:1001` 导出为普通函数，**未包 `React.memo`**。
- 缓解事实：`SessionBubbleList.tsx:1011/1057` 用 `useMemo` 绑定稳定引用源 → 派生计算不重算；但组件函数体与全量 JSX diff 仍每次执行。
- 建议：`React.memo` 包裹，或提升到 `RootApp`（`src/client/index.ts:106-131`）与 CharacterOverlay 并列。**不可在 runtime 层加 diff（冲突 ADR-0016）**。
- 收益：中-高。风险：低。

### 中影响

**M1 — 过渡素材时长解析：整文件 fetch 进内存**
- 证据：`CharacterOverlay.tsx:448` → `webp-duration.ts:76-80` `await res.arrayBuffer()` 取整文件；`:73` `durationCache` 按 url 缓存一次但**模块级、无清理入口**。
- 事实：单个 transition webp 2.37–12.37 MB，首次播放需完整下载 + 分配 + JS 逐 chunk 解析（`:47-70`）。
- 建议：host 提供轻量 `/api/dsh-jx/duration?p=`（只读前若干 KB），或构建期生成 `assets/manifest.json` 固化时长。
- 风险：低；新增长生命周期缓存须按 ADR-0017 在 dispose 清空。

**M2 — `backdrop-filter: blur(10px)` 大面积覆盖宿主表面**
- 证据：`welcome-backdrop.ts:182` `GLASS_BLUR_PX = 10`；`:235-238` 注入；选择器矩阵 `:187-214` 覆盖 composer-card / sidebar / `role=dialog|menu|listbox|tooltip` / radix-popper / 插件容器 / `[class*="bubble"]` / `code` 等十余类。
- 事实：壁纸激活时上述元素全部毛玻璃。已有降级：`:241-246` reduced-motion 下 `none`。
- 建议：收窄矩阵或对高频重绘元素（bubble/code/listbox）降为纯 alpha。
- 风险：改变 ADR-0027 D2/D8 视觉契约。

**M3 — `session-messages` 的 inspect 无缓存、无 in-flight 去重**
- 证据：`session-messages.ts:274` 直接 `controller.inspect(sessionId)` 后 `writeJson`（`:275-278`）；全文件检索 `cache|inflight|dedup|Map<` **0 命中**。
- 建议：按 `sessionId` 短 TTL 缓存 + in-flight Promise 去重。
- 风险：与 ADR-0028 冲突（缓存须随 archived/retention 变更失效）。

**M4 — ai-title 服务端无缓存/去重；客户端缓存无界且 TTL 可被全局覆写**
- 服务端证据：`ai-title-route.ts:156` `llmClient.chat` 前无 cache/inflight 判定；`:132` 每次 `scope.get()`。
- 客户端证据：`dynamic-title.ts:333` `new Map()` **无 delete/无淘汰**；`:402` `ttlMs` 是闭包级变量（`:330`），被最后一次响应**全局覆盖**；`:336-411` 无 in-flight 去重。
- 事实修正：工单「无节流无缓存」假设部分不成立——客户端已有 TTL 15min + 节流 30s。
- 建议：服务端按 `sessionId+updatedAt` 短 TTL + in-flight 去重；客户端 cache 加 LRU 上限，`ttlMs` 改为按 entry 存储。
- 风险：低。

**M5 — warp 涟漪每次 pointerdown 触发强制同步布局**
- 证据：`warp.ts:190-193` `el.style.animation = "none"; ...; void el.offsetWidth; el.style.animation = "";`
- 建议：改 `el.getAnimations().forEach(a => a.cancel())` + `anim.play()`，或 rAF 内重置。风险：低。

### 低影响

- **L1 `warp-controller.onFrame` 是死代码，visible 守卫恒真**：`:53` 声明、`:90-101` 实现，全 `src` 无调用点 → `:87-88` 置 true 后再无人置 false → `warp.ts:157/186/221/233` 的 `visible` 守卫恒真，「停下即隐」（`:6-8`）失效。附带好处：因此没有 rAF 常驻循环。建议二选一：接上 rAF 恢复降级语义，或删除守卫明确「无淡出」。
- **L2 fall 叶子带 CSS `filter: drop-shadow`**：`fx.css:90/99` 作用于 8 个 WAAPI 动画元素（`fall.ts:118/122-127`）；推断可能阻碍纯合成层路径（未实测）；建议把阴影烘进 SVG data-uri 素材。
- **L3 客户端产物关闭压缩**：`vite.config.ts:161` `minify: false`（`:158-161` 说明：为让 `generateBundle` 整体包裹时 `module`/`exports` 变量名确定）。开压缩需先解决保留变量名，否则破坏确定性假设。
- **L4 lib 产物现状**：`lib/index.js` 179.77 KB（host）；`lib/` 被 `.gitignore:11` 忽略；`lib/client.js` 当前工作区不存在，需 `npm run build:client` 后才可测。
- **L5 `dynamic-title` 缓存无界**：已并入 M4。

### tick 频率（工单明确问题）

- **生产值 = 1000ms**（事实）：`overlay-session-runtime.ts:375` `opts?.tickIntervalMs ?? 1000`；`:1403` `setInterval(tick, tickIntervalMs)`；`src/client/index.ts:191-194` 未传 → 走默认。
- 补充事实：`tick()`（`:1315-1401`）只在 deadline 到期时才 `emit()`，非每拍 emit；但 `emit()` 一旦触发即无条件重建快照（见 H4）。

### 与既有 ADR 的冲突

| 候选点 | 冲突 ADR | 性质 |
|---|---|---|
| H4「runtime 层加 diff 再 emit」 | **ADR-0016** | **直接冲突、已被否决**。ADR-0016 原文：runtime 无条件 emit 语义保留，UI 侧门槛吸收引用抖动；runtime 去抖改动面大且需重验 `useSyncExternalStore` 通知语义（`focusNonce` 等），收益重复。→ 只能走 UI 侧隔离。 |
| H4 若复用 playback 数组引用 | ADR-0016 | playback 的**内容**是推进的唯一身份，引用复用不得改变内容；加 nonce 会强制重播。 |
| M1/M3/M4 新增模块级缓存 | **ADR-0017** | 可重入约束：新增长生命周期状态须在 dispose/teardown 清空，否则 HMR 重载后跨实例残留（与「孤儿浮层」同族缺陷）。现存先例：`webp-duration.ts:73` `durationCache` 无清理入口。 |
| M3 inspect 缓存 | **ADR-0028** | 记账/retention/archive 排除：缓存须随归档与保留变更失效，否则退回陈旧数据。 |
| H1/M2 壁纸改造 | **ADR-0024 / ADR-0027** | 收窄观察范围/玻璃矩阵会改变视觉契约（`GLASS_SURFACE_SELECTORS :187-200`），需重测。 |
| H2 素材重编码 | ADR-0012 / ADR-0021 | 触碰循环缺陷素材修复与 chroma key 重转的既有资产口径。 |
| H3 缓存策略调整 | 前车之鉴 | `asset-routes.ts:87-90` 记录强缓存事故，**不可回退到强缓存**。 |

### 事实 / 推断边界

- **已核实事实**：全部文件:行号引用、assets 体积数据、`tickIntervalMs` 生产值、`onFrame` 无调用点、readFile-before-ETag 顺序、`SessionBubbleList` 未 memo、`emit()` 无条件重建快照、三条被证伪假设、监听器成对情况。
- **推断（未实测）**：H1 触发频率与耗时、H2 可压缩空间、M1 累计内存量、M2/M4/L2 实际成本、L3 开压缩收益。
