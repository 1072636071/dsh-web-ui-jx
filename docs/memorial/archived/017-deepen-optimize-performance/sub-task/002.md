### §2 新的深化候选（S1–S8 未覆盖）

**C1【P0】`writeJson` 出现第二份实现 + 同模块重复同名导入绑定**
- 现象：S5 收敛后，后续 ADR-0032 工作又新建 `json-response.ts` 提供逐字相同的 `writeJson`；`import-api.ts` 同时 import 了两个同名 `writeJson`。
- 证据：`http-shared.ts:29-40` 与 `json-response.ts:13-20` 函数体逐字等价；`import-api.ts:34-38` 从 `./http-shared.ts` 导入 `{ isSafeRelativePath, parseUrlPathname, writeJson }`，`:47` 又从 `./json-response.ts` 导入 `{ writeJson }`；调用方已分裂——`session-messages.ts:32` 只用 json-response、`ai-title-route.ts:27` 只用 http-shared、`import-api.ts` 两者都 import（主代理 grep 复核，2026-08-30）。
- 建议：删除 `json-response.ts`；`session-messages.ts:32` 改为从 `http-shared.ts` 导入；删除 `import-api.ts:47`。
- 收益：单一实现，S5 成果不再漂移。风险：低（行为逐字节等价）。

**C2【P1】浮层位置持久化未入工厂**
- 证据：`src/client/state-machine/overlay-position.ts:52` `const OVERLAY_POS_STORAGE_KEY = "jx-overlay-pos"`、`:113` 注释「容错对齐 skin.ts / fx/index.ts」、`:323` 初始化直读 localStorage（主代理 grep 复核，2026-08-30）。
- 事实：这是 S1–S4 收口后**唯一剩余的裸 localStorage 持久化点**（skin / overlay-settings / 气泡上限 / 保留模式 / 欢迎背景均已入工厂）。
- 摩擦：位置是 `{x,y}` 结构值，工厂现仅支持 bool / number / id-set 三型，缺 **JSON 结构值**构造器。
- 建议：工厂补第四型（泛化 `createPersistentSetting<T>` 已支持，只需确认无需新增）——位置可直接用带 `parse` 的 `createPersistentSetting<{x,y}>`；或评估位置是否本就该走不同生命周期（拖动中只改内存、松手才写盘——`overlay-position.test.ts:426` 已锁定「move 不写 localStorage」语义，改造需保留该语义）。
- 风险：中。该语义差异（实时跟手不写盘）是**有意设计**，直接套工厂可能破坏。

**C3【P2】client 设置壳的遗留重复**
- 证据：`overlay-settings.ts:25-34` 两实例 + 具名导出；`skin.ts:24-28` 的 bool parse 闭包在 S1 后是否仍重复需逐行复核。
- 判定：S8 结论为「维持现状，不加声明式表」——**不实施**。仅登记为观察项。
