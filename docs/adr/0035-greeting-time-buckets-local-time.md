# ADR-0035 — 问候时段：05/12/18/23 四档 + 浏览器本地时区 + 挂载时算一次

状态：已接受（待实施）
日期：2026-09-03
关联：ADR-0033（开槽）、memorial 017

## 背景

四句问候语需要一个时段 → 文案的映射。用户给的文案固定为四档（上午好 / 下午好 / 晚上好 / 该休息了），所以档数已定，唯一要决策的是**边界小时**、**时区来源**，以及**长时间停留时是否翻档**。

## 决策

### 1. 边界：05 / 12 / 18 / 23

| 档 | 区间 | 文案 |
| --- | --- | --- |
| 上午 | 05:00–11:59 | 上午好，{name}，有什么需要我搞定的么？ |
| 下午 | 12:00–17:59 | 下午好，{name}，有什么需要我搞定的么？ |
| 晚上 | 18:00–22:59 | 晚上好，{name}，有什么需要我搞定的么？ |
| 该休息 | 23:00–04:59 | 该休息了，{name}，让我来做吧，好好休息哦。 |

判定是 wrap-around：`hour >= 23 || hour < 5`。这是本决策唯一的易错点，边界（4/5、11/12、17/18、22/23）必须有专门测试。

### 2. 时区：浏览器本地时间

hero 是纯 client 渲染，Host 完全不参与，取服务端时区只会与实际感受不符。不做时区配置。

### 3. 刷新时机：挂载时计算一次，不挂 timer

hero 只在**空会话**显示，用户一发消息就切走；而且每次新建会话 hero 都会重新挂载——"新建会话"本身就是天然的刷新时机。为一句装饰性文案挂常驻定时器是过度工程。

**已知且接受的行为**：22:58 打开一个空会话干放到 23:01，仍显示「晚上好」。

### 4. 不做英文文案

本插件是中文单语角色插件，无 locale 体系。ADR-0033 的宿主改动不新增 locale key（fallback 沿用原有 `hero.headline` 的 zh/en），因此不触发 `verify-client-ui-i18n`。

### 5. 「预览版」badge 保留不动

slot 只替换 headline 那个节点；badge 是兄弟节点（宿主 `EmptyHero.tsx:125`），与问候语互不影响。

## 被否决的替代方案

1. **B 方案 06 / 12 / 18 / 00**（该休息 = 00:00–05:59）——休息档是 `hour < 6` 的连续区间，代码最干净。但 **23:00–23:59 会显示「晚上好」**，恰恰漏掉最该触发关怀的那个钟点。否决。
2. **C 方案 22 / 05 / 12 / 18**（该休息提前到 22 点）——关怀最激进，但晚上档被压到 18–21:59，而 18–22 往往是人干活最起劲的时候，这时说「该休息了」容易扫兴。否决。
3. **每分钟 `setInterval` 对齐刷新**——永不过期，但要常驻 timer + 卸载清理 + fake-timer 测试，为低频停留的装饰位轮询不划算。否决。
4. **`setTimeout` 精确唤醒到下一个边界**——精准、无轮询，但标签页休眠后会被节流，醒来时可能已跨过多个边界，还得补一次重算，复杂度全在这。否决。
5. **时段边界做成可配置**——仓库取向是"不为假设需求加配置项"；边界是文案语义的一部分，不是随部署变化的选择。否决。
