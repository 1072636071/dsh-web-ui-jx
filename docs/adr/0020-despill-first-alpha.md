# ADR-0020: 色度键 alpha 改用 despill-first 距离（修衣物发红/发紫）

## 状态

已实施（2026-08-23）。

## 背景

2026-08-22 批次变体素材入库后，用户报告「新处理的动画素材颜色很红」，
具体表现为**衣物大面积呈品红/紫红**，尤其在深色主题下明显。

## 诊断

1. **症状定位**：用户确认「衣服很红」，硬刷新后仍红 → 排除缓存，锁定内容本身。
2. **定责实验**：对 working-v2 裙部 crop 按 alpha 分层统计色相：
   - 不透明段（α>240）：紫簇 33%，meanRGB (123,107,114) — 已偏品红；
   - 半透明段（α180–240）：紫簇 **82.5%**，meanRGB (90,**61**,82) — G 被压垮 30 点；
   - 软边段（α80–180）：紫簇 **86.0%**，meanRGB (93,**54**,84) — G 更低。
3. **根因**：源视频衣物阴影带绿色环境光反射（绿幕底色 RGB≈(0,211,51)）。
   色度键的原始距离 `dist(raw, bg)` 把这些「绿灰阴影」误判为半透明（距离偏小），
   随后 un-premultiply `c' = (c − (1−α)·bg)/α` 减绿底、除以小 α，
   G 通道塌陷而 R/B 被放大 → 整片品红/紫红。

## 决策

**alpha 距离改用「先去溢色」后的颜色计算**（despill-first）：

1. 先按既有 spill 条件（g > mean_rb+4 且 sat<50 或 dist_raw<190）算一份
   「去溢色参考色」`g_ref = min(g, mean_rb+4)`；
2. 距离对「同样去过溢色的底色」计算：
   `dist = ||(r, g_ref, b) − (gr, min(gg, (gr+gb)/2+4), gb)||`；
3. 该距离上套原有坡道（42→105→线性）得 α。

效果：
- 纯绿幕经同一变换后贴近去溢色底色 → 距离归零 → α→0 ✓
- 绿灰衣料去绿后回到中性灰 → 远离该参考点 → α→1 ✓
- 金饰等高饱和暖色由 spill 条件保护（sat≥50 且 dist_raw≥190 不参与）✓

un-premultiply 与 despill 后续阶段保留不变；真实混合边缘的 α 现在偏高、
修正温和，绿残留由 despill 压回。

## 后果

- **边缘硬度**：真实 fabric↔screen 混合带的 α 从 ~0.5 升到 ~1，边缘略硬 1–2px；
  360×640 展示尺度下人眼不可辨，QC-b 相邻帧块差仍在合法范围（top3 ≤137）。
- **阈值复用**：QC-b 上限 165 仍适用；未来若再升级图像处理需重跑校准。
- **运行期扩展**：新增 working-v5（画上半圆弧），`variant-rotation.ts` 轮换池
  从 4 项扩展到 5 项。

## 什么本可以防止这个 bug

1. **alpha 估计的边界测试**：管线设计时应加入「绿灰阴影」合成帧测试——
   把经典态 idle 的裙部叠加绿色 tint（模拟绿幕环境光），验证 chroma_key 后
   裙部仍保持中性白/灰，而非品红。
2. **garment 颜色一致性 QC 门**：现有三道质检（符咒在场 / 局部突变 / 首尾姿态）
   均不感知衣物色相。应新增「裙部/外袍 vs 经典态 canonical 参考」的逐帧
   色相差分门，作为硬闸。
3. **目检条底色贴近真实展示背景**：本次若第一轮就在浅色底目检裙部，
   紫红会早几小时被发现，而非被中灰底色掩盖。
