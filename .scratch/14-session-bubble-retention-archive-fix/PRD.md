# PRD — 会话气泡跨刷新留存 + 归档排除修正

- Feature: `14-session-bubble-retention-archive-fix`
- Status: `ready-for-agent`
- Source: memorial 014 `docs/memorial/archived/014-session-bubble-refresh-archive-bugs/`（Q1–Q3 用户拍板 + 自主定案 D-seen*/D-grp1/D-prune1）+ ADR-0028

## 问题陈述

会话气泡列是用户的「待办提醒板」：任务完成的气泡留在那里，提醒用户哪些事还没去看、没去办结。当前有两个信任问题：

1. **提醒靠不住**：页面一刷新，所有已完成气泡集体蒸发——包括用户根本没来得及看的。根因有两层：SDK 的 completed 位是**连接内活事实**（runtime 以本页面加载内的 running→idle 边沿武装提醒，「加载时已空闲的会话得不到提醒」，刷新即失忆）；插件自身的记账集合又在挂载首帧被空列表 prune 误清（`sessions.list` 初始快照是「已定义但为空」`phase:"pending"`，而裁剪守卫只防 `undefined`），连「点过保留」的记忆也一起丢。
2. **清理不生效**：在宿主侧边栏归档了会话，气泡却还赖在列里——归组模型下只要根会话还有任一存活成员，已归档的根继续当锚点显示；保留模式总开关关闭时归档排除更是整体短路失效。

## 解决方案

让气泡列的进出场都听话：

- **进场后不擅自离场**：客户端自己持久记账「完成见闻集」——凡观察到完成态的会话记入本地集合，刷新后由本地记忆撑住可见性，直到用户亲手收起（手柄/Delete，可逆）或在宿主归档（不可逆）。同时修好裁剪时机：只有会话列表基线真正就绪后才允许清理记账，杜绝挂载期误清。
- **归档即退场**：归档是宿主级事实，任何配置下都生效——普通会话归档后气泡消失；工作流根会话归档视为整条工作流办结，整组气泡消失（组内还有活动成员时暂留到静止，防止活工作流从视野里蒸发）。

## 用户故事

1. 作为任务发起人，我希望已完成的会话气泡在页面刷新后仍然显示，以便我不会忘记哪些任务还没跟进处理。
2. 作为用户，我希望我点开查看过的气泡刷新后依然保留，以便「看过但没办结」的任务持续提醒我。
3. 作为用户，我希望我收起过的气泡刷新后保持隐藏，以便已清理的提醒不会复活打扰。
4. 作为用户，我希望某个会话**再次**完成时自动解除之前的收起记忆、重新弹出提醒，以便旧的收起不会吞掉新一轮完成信号。
5. 作为用户，我希望收起操作保持现状（左侧手柄点击 / Delete·Backspace 键盘，均为可逆的本地记账），以便不改变已经习惯的操作方式。
6. 作为多代理工作流使用者，我在侧边栏归档一条工作流的根会话后，希望整个归组气泡立即消失，以便界面如实反映「这条工作流已办结」。
7. 作为多代理工作流使用者，若归档根会话时组内还有运行中/等待确认的子代理，我希望该组暂时保留可见，以便进行中的工作不从视野里消失。
8. 作为多代理工作流使用者，我希望上述暂留的组在全部成员静止后自动消失，以便无需二次手动清理。
9. 作为用户，我希望无论保留模式总开关开着还是关着，已在宿主归档的会话都不再出现在气泡列，以便「归档」的语义始终权威、不受显示开关否决。
10. 作为用户，我希望关闭保留模式总开关后，除归档排除外的其余行为完全回到旧版（完成气泡不再跨刷新留存），以便这个开关仍是可靠的降级手段。
11. 作为用户，我希望 localStorage 不可用或数据损坏时功能照常降级（本次会话内生效/回落默认值），以便异常环境不白屏、不崩功能。
12. 作为开发者，我希望记账集合随会话列表变化惰性裁剪、仅在确有删除时才写盘，以便存储不膨胀、订阅无写循环。
13. 作为开发者，我希望全部可见性判定落在可独立测试的纯逻辑层，以便回归护栏能做逐条目比对。
14. 作为用户，我希望已不在会话列表中的记账 id 自动失去效力，以便残留记忆不会产生幽灵气泡。

## 实现决策

> 全部决策沿用既有接缝，**零新建 seam**。以下不含文件路径，模块名即领域词汇；完整根因证据与方案对比见 ADR-0028 / memorial 014。

- **D1 — 完成见闻集（seen）存储**：复用既有的 id 集合 store 工厂（kept/dismissed 同款实现）新增第三个实例，localStorage 键名 `jx-bubble-keep-seen`；读写容错对齐既有纪律（读失败/形状不符回落空集，写失败静默仅本次会话生效）。
- **D2 — 投影范围扩展**：范围过滤入选条件从 `running || completed || kept` 扩展为 `running || completed || kept || seen`；dismissed/archived 的隐藏优先级高于一切入选依据；「running 或等待交互的条目不被记账隐藏」的既有豁免规则原样保留（活动与紧急信号优先）。
- **D3 — 记账时机**：组件层在会话快照派生后，把所有 `completed === true` 的条目 id 提交进 seen 集（add 幂等，无需维护上一帧对照表）；点击跳转的 kept 记账路径零改动。seen 只增不减（除裁剪），不做过期时间。
- **D4 — 裁剪门控（治挂载误清）**：三个记账集合（kept/dismissed/seen）的惰性裁剪统一加守卫——会话列表快照存在**且到达 ready 相位**才执行；pending 相位（含挂载首帧的空基线）一律跳过。「确有删除才写盘并通知」的防写循环纪律不变。
- **D5 — 根归档整组隐藏**：归组装配阶段新增组级判定——根会话命中归档集且组内不存在豁免成员（无运行中、无等待交互者）⇒ 整组从气泡列消失（SDK 会话行不动，仅投影层隐藏）；存在豁免成员 ⇒ 组维持现状渲染，全部成员静止后自然落入隐藏分支。判定落纯逻辑层。
- **D6 — 归档排除脱离开关**：archived 隐藏提升到保留模式总开关判定之外，任何开关组合下都生效。回归护栏语义随之改写：「总开关关 = 输出与现状逐条目全等」收窄为「**除归档排除外**与现状逐条目全等」；受影响的既有护栏断言同步改写。
- **D7 — 开关门控不变项**：kept/dismissed/seen 三集合仍只在总开关①开启时参与投影（关 = 完成气泡不再跨刷新留存，回到 SDK 原生瞬态语义）；「新一轮 completed 上升沿清除该条 dismissed」的生命周期逻辑原样保留。
- **D8 — 兼容性**：既有用户的 `jx-bubble-keep-*` localStorage 键全部继续有效，新键增量添加，无迁移。

## 测试决策

- **纯逻辑层为主战场**（先例：`tests/client/session-bubbles.test.ts` 既有的 keep-context 回归段——平铺基准逐条目比对模式直接复用）：覆盖 seen 入选、dismissed/archived 优先于 seen、running/pending 豁免不被记账隐藏、根归档+全静止成员 ⇒ 整组不可见、根归档+豁免成员 ⇒ 组保留、归档排除在总开关关闭下仍生效、总开关关闭时除归档排除外与基准全等（改写后的新护栏）。
- **配置存储层**（先例：`tests/client/persistent-setting.test.ts` / `skin.test.ts` / `overlay-settings.test.ts` 的 localStorage 存取测试模式）：seen store 的 add 幂等与引用稳定、prune 仅确有删除才写盘、脏数据/JSON 解析失败回落空集、写失败静默。
- **组件接线保持薄壳**：记账提交与相位门控尽量以纯逻辑表达后单测；如需 DOM 级验证，对齐 `tests/client/character-overlay-crossfade.test.ts` 的 createRoot 渲染先例，不为覆盖率堆重 DOM 测试。
- **既有护栏改写**：现测试中「总开关关闭时携带记账集合仍与不传参输出全等」的断言，按 D6 新语义改写（归档排除成为唯一例外），防止旧护栏锁死新行为。
- **质量门槛**：typecheck + 全量测试通过后 `npm run build` + `npm run verify`（AGENTS.md 构建验收约束，21 项检查）。

## 超出范围

- 宿主/SDK 侧持久化 completed 位（跨仓库改动，已在 grill 中否决——ADR-0028 记录理由）。
- 恢复插件内归档入口 UI 或引入 unarchive 能力（ADR-0026 改型已移除归档区，契约层亦无 unarchive）。
- 归组成员重锚为孤儿泡、归档根灰显标记（Q2 已否决的两个替代案）。
- kept/dismissed/seen 三集合合并或既有键名迁移（D8 明确增量兼容）。
- 配置②「拖拽归档」开关在 ADR-0026 改型后已无任何投影职责，属死配置位——其清理另行处理，不入本规格。
- 气泡排序、时间戳重排等投影展示增强。

## 补充说明

- **根因证据锚点**：SDK runtime 的完成提醒同步函数注释原文「First observation only records the running bit — sessions already idle at load get no reminder」——completed 位连接内活事实是本规格成立的前提事实；会话列表快照初始态为「已定义但为空 + pending 相位」是挂载误清的前提事实。两者均已在 memorial 014 背景事实段查证闭环。
- **边界行为一致性**：任务在 GUI 关闭期间完成、下次打开页面时早已空闲的会话，SDK 不报完成态、客户端也无从见证——这类会话不出现气泡（与现状一致，非本规格缺陷）。
- **来源链**：用户报告（2026-08-26）→ memorial 014 grill（Q1 见闻集方案 / Q2 整组隐藏 / Q3 排除脱离开关，细节授权 captain 定案）→ ADR-0028 → 本 PRD。
