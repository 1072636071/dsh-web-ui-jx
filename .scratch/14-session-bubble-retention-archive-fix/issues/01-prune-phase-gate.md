# 记账裁剪相位门控（治挂载期误清记账）

**Status:** resolved

**构建内容：** 修复「每次刷新页面都清空气泡记账」的缺陷——用户点击保留的气泡、收起的记忆，刷新后得以幸存。这是见闻集功能的地基：不修它，任何新增的持久记账都会在挂载首帧被空列表裁剪清空，整个留存特性自我失效。

根因速记：会话列表快照的初始态是「已定义但为空 + pending 相位」，而记账集合的惰性裁剪守卫只防「快照不存在」——守卫对实际初始态完全失效，挂载即以空列表裁剪 kept/dismissed 并写盘。

**验收标准：**

- [ ] 会话列表基线未就绪（pending 相位）时，kept/dismissed（及未来任何记账集合）一律不执行裁剪
- [ ] 基线就绪后裁剪行为不变：只保留列表中存在的 id；仅在确有删除时写盘并通知（防写循环回归）
- [ ] 端到端验证：点击一个已完成气泡保留 → 刷新页面 → 气泡仍在；收起一个气泡 → 刷新 → 保持隐藏
- [ ] 全量测试通过；`npm run build` + `npm run verify` 验收通过
