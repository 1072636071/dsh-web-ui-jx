# PRD — 会话气泡独立成子包（库 + 薄壳插件）

- Feature: `15-session-bubble-package`
- Status: `ready-for-agent`
- Source: memorial 014 `docs/memorial/archived/014-session-bubble-package/`（Q1–Q4 用户拍板 + 授权自行决策 D5–D13）+ ADR-0029

## 问题陈述

本项目最有价值、复用潜力最大的模块是会话气泡列：归组引擎（根祖先锚定 + 子代理折叠）、保留模式（kept/dismissed 记账）、跨刷新留存（完成见闻集）、拖拽收纳双投放区——纯逻辑层已经与宿主完全解耦。朋友的 DSH 宿主（deepseek-harness）也需要这套会话管理气泡，但当前实现深嵌在本插件内：

1. **不可复用**：气泡逻辑、组件、配置、样式散落在本插件内部，与 SettingsCard、CharacterOverlay、浮层、素材等纠缠在一起，朋友无法单独拿走使用。
2. **无法独立交付**：没有独立的构建产物与安装入口，朋友不能 `dsh plugin add` 装完即用，也不能在自己的 DSH 插件里 import 气泡库二次接线。
3. **CSS 依赖宿主**：`--jx-*` token 定义在本插件 `body[data-dsh-jiangxiao]` 作用域下，脱离本插件环境气泡颜色全崩；`--dsw-*` 官方 token 依赖 DSH 宿主提供。
4. **演进漂移风险**：若复制一份实现给朋友，后续气泡演进（保留模式、归档、归组优化）两处各改各的，单一事实源断裂。

## 解决方案

把会话气泡列拆成**库 + 薄壳插件**两层，就地把当前仓库改造为 monorepo（npm workspaces）：

- **库 `dsh-session-bubble`**：通用 React 组件库，独立 npm 发布。包含纯逻辑（`buildBubbleGroups` 归组引擎 / 拖拽判定 / `displayTitle`）、SDK 投影、组件 `SessionBubbleList`、配置与记账模块、样式 + 自带 `--jx-*` 默认值的 `bubble-theme.css`（作用域限定在气泡根容器，深浅双值随 `data-ds-dark-theme` 切换，宿主同名变量自然覆盖）。
- **薄壳插件 `dsh-session-bubble-plugin`**：最小 DSH bundle 插件，极简 fixed 容器承载 `SessionBubbleList`，`inject: sessions/workspaces`，朋友 `dsh plugin add` 装完即用。
- **本插件（dsh-web-ui-jx）原位不动**：根插件改为 import 库，与薄壳共享单一事实源；构建/验收链路适配多包结构，但根插件路径零迁移。

数据契约不抽象：消费方同为 DSH 宿主，`ISessions`/`IWorkspaces` 接口原样消费。

## 用户故事

1. 作为 DSH 宿主使用者（朋友），我想要一条命令把会话气泡装进我的宿主，以便无需改任何代码就能用上与主项目一致的气泡列。
2. 作为 DSH 宿主使用者（朋友），我希望安装后气泡列的归组/保留/拖拽/跨刷新留存行为与主项目完全一致，以便体验不打折。
3. 作为 DSH 宿主使用者（朋友），我希望气泡列在无本插件 `--jx-*` token 的环境下颜色依然正常，以便不出现鎏金变灰、朱砂变暗的样式崩溃。
4. 作为 DSH 宿主使用者（朋友），我希望我的宿主深浅主题切换时气泡自动跟随，以便视觉与宿主环境一致。
5. 作为 DSH 插件开发者（朋友），我想要在自己的 DSH 插件里 import 气泡库并二次接线，以便把气泡嵌入我的既有布局而不是固定悬浮。
6. 作为 DSH 插件开发者（朋友），我希望库暴露的组件、纯逻辑、配置操作有清晰的类型与 API，以便集成时无需读插件源码。
7. 作为本插件的用户，我希望本次改造后气泡列外观与交互行为保持不变，以便不承受功能回归。
8. 作为本插件的用户，我希望本插件与薄壳插件若装在同一宿主，气泡的保留/收起/完成记忆共享同一份本地数据，以便不出现两个互相打架的气泡列表。
9. 作为本插件的用户，我希望保留模式与拖拽归档的开关设置依然在设置卡里可用，以便配置入口不因拆包而消失。
10. 作为开发者，我希望根插件与薄壳插件消费同一个库实现，以便气泡后续演进只改库一处、两处同时生效。
11. 作为开发者，我希望库的纯逻辑层（归组、判定、标题、配置操作）保持零依赖纯函数，以便测试不依赖宿主/SDK/DOM。
12. 作为开发者，我希望库能独立构建出可发布的产物（ESM + 独立 CSS），以便可走 npm publish 分发。
13. 作为开发者，我希望薄壳插件能构建出 DSH bundle 双半区产物并带自有挂载配置，以便 `dsh plugin add` 可安装。
14. 作为开发者，我希望 monorepo 改造不动根插件既有路径与 files 清单，以便不引入大规模回归风险。
15. 作为开发者，我希望现有 5 类气泡测试随源码迁入库并继续通过，以便拆包不丢回归护栏。
16. 作为开发者，我希望构建与发布前验收保持可用（typecheck + 测试 + 构建 + 验收脚本），以便改动可被验证。
17. 作为维护者，我希望库的 localStorage 键保留 `jx-*` 前缀并集中单点管理，以便本插件与薄壳共享记账数据、语义一致。
18. 作为朋友，我希望拿到的是「装完即用」的最小插件而非需要自己拼装的碎片，以便不把交付变成负担。

## 实现决策

> 全部决策来自 memorial 014 grill（Q1–Q4 用户拍板，D5–D13 授权助手定案）与 ADR-0029。以下不含文件路径；模块名即领域词汇。

### 包形态与仓库组织

- **D1 — 消费方环境 = DSH 宿主**：数据契约保留 `ISessions`/`IWorkspaces` 接口原样消费（`sessions.list`/`sessions.open`/`workspaces.list`/`workspaces.archiveSession`），不造通用 SessionLike 抽象层。
- **D2 — 两层包形态**：内部通用 React 组件库（独立发布）+ 顶部最小 DSH bundle 薄壳插件（装完即用）。本插件消费同一库实现，单一事实源。
- **D3 — monorepo 轻量就地改造**：根目录保持本插件原位不动，根 package.json 增 `workspaces: ["packages/*"]`；新增库与薄壳两个子包。否决根插件迁入 packages/（路径变更风险高、收益小）。子包不进根包 files 清单。

### 库的构成与公共 API

- **D4 — 库构成**：迁移纯逻辑（归组引擎/拖拽判定/标题）、SDK 投影、组件、上限配置、保留模式记账、持久化工厂、样式；新增 `bubble-theme.css`（`--jx-*` 默认值，作用域限定气泡根容器，深浅双值随 `data-ds-dark-theme`，宿主同名变量自然覆盖）。`--dsw-*` 为 DSH 官方 token，由宿主提供，库不复制。
- **D5 — 导出面**：`SessionBubbleList` 组件 + 纯逻辑（`buildBubbleGroups`/`displayTitle`/类型）+ 配置操作（上限/保留开关/拖拽归档开关等）。根插件 SettingsCard/CharacterOverlay 改 import 库。
- **D6 — 数据契约**：组件以 SDK `SessionListState` 为输入（经库内投影层转自有形状），不定义业务无关的通用数据层。

### 配置与存储

- **D7 — localStorage key**：保留 `jx-*` 前缀、集中到库内存储键单点。根插件与薄壳同宿主时共享同一份记账数据（同一用户同一会话列表，语义合理）。

### 薄壳插件

- **D8 — 薄壳形态**：DSH bundle 插件骨架（单行挂载），`inject: sessions/workspaces`；极简 fixed 定位容器承载 `SessionBubbleList`（无浮层、无素材、无设置卡）。挂载位置/锚点在实施阶段细化；host 半区是否必须列入实施调研。

### 测试 / 构建 / 发布

- **D9 — 测试迁移**：气泡相关测试（归组引擎/投影/保留记账/组件/拖拽手柄）随源码迁入库包；vitest 配置适配 workspace。
- **D10 — 构建**：库 = vite lib mode（ESM + CSS 抽取，独立产物）；根插件从库 import 走 workspace 源码构建（vite 直接打包库源码）；薄壳 = 双半区构建（复用 CSS 内联模式，CLIENT_ID 换名）+ 自有挂载配置。
- **D11 — 验收**：`verify-release.mjs` 保持验收根插件；库/薄壳发布前以 build + typecheck 兜底。
- **D12 — 发布策略**：库 `dsh-session-bubble` npm publish（access public）；薄壳 `dsh-session-bubble-plugin` npm publish 或 `dsh plugin add link:` 本地安装（朋友开发期）；根插件照旧。
- **D13 — 配置归属**：保留模式/上限配置操作函数从库导出，根插件 SettingsCard 照旧接线；薄壳不带 SettingsCard（最小化），保留模式默认开。

### 模块（seam）

| 模块 | 改动 | 性质 |
| --- | --- | --- |
| 会话气泡纯逻辑引擎（归组/拖拽判定/标题所在层） | 原样迁入库，导出为公共 API | 既有接缝，库内不变形 |
| SDK 投影层 | 原样迁入库，SDK 类型随包声明 | 既有接缝 |
| 气泡列组件 `SessionBubbleList` | 迁入库；输入以 SDK 快照/接口面为 props 契约 | 既有接缝，接口面成为库的公共 seam |
| 配置与记账模块（上限/保留/归档开关 + 持久化工厂） | 迁入库，操作函数导出 | 既有接缝扩展 |
| 样式 + `bubble-theme.css` | 样式原样迁入；`--jx-*` 默认值新增自洽层 | 新增 seam（唯一新建：token 默认值作用域） |
| 薄壳插件 | 新骨架，消费库组件 | 新增薄壳（最小，非测试 seam） |
| 根插件接线 | SettingsCard/CharacterOverlay 改 import 库 | 消费侧接线 |

## 测试决策

- **纯逻辑层为主战场**（先例：现有归组引擎测试的平铺基准逐条目比对模式）：`buildBubbleGroups`/拖拽判定/`displayTitle`/配置操作全部以纯函数单测，测外部行为不测实现细节；迁移不改断言语义，保证拆包零回归。
- **SDK 投影层**（先例：投影测试）：以 SDK 快照形状构造输入，断言投影后自有形状逐字段正确；不依赖真实 runtime。
- **组件渲染测试**（先例：既有气泡列渲染测试的 createRoot 先例）：以 props 契约注入受控快照，验证渲染分支与交互副作用；保持薄壳。
- **配置/记账存储**（先例：持久化设置与 localStorage 存取测试模式）：读写容错、脏数据回落默认值、写失败静默降级。
- **薄壳插件**：构建产物非空 + 挂载配置语法校验，不堆 DOM 级测试。
- **质量门槛**：typecheck + 全量测试通过后，根插件 `npm run build` + `npm run verify`（AGENTS.md 构建验收约束）；库/薄壳各自 build 兜底，发布前验收。

## 超出范围

- **通用数据抽象层**：消费方同为 DSH 宿主，`ISessions`/`IWorkspaces` 不抽象（D1 明确否决）。
- **薄壳功能完整性**：不带 SettingsCard、浮层、素材；保留模式默认开，无设置入口。
- **库的完整主题系统**：只带 `--jx-*` 默认值自洽，`--dsw-*` 依赖宿主；不做全量设计令牌迁移。
- **根插件路径重构**：根插件不迁入 packages/，files/构建/验收链路最小适配。
- **气泡新功能**：本规格只做拆包，不引入新的气泡行为。
- **host 半区必需性查证与挂载锚点细化**：列为实施阶段调研项（D8 注记）。
- **本地化/多语言、无障碍增强**等库级通用打磨，另行排期。

## 补充说明

- **单一事实源**：根插件与薄壳共享库实现；后续气泡演进（保留、归档、归组优化）只改库一处，两处同时生效。
- **共享记账语义**：同宿主双插件共享 `jx-*` localStorage 数据，语义为「同一用户同一会话列表」，非缺陷。
- **构建优先级**：库 import 走 workspace 源码（vite 直接打包），不强制先发布库再构建根插件——开发期零发布依赖；发布期按 npm 链路走。
- **朋友交付路径**：开发期 `dsh plugin add link:<path>` 本地安装；稳定后 npm publish。
- **来源链**：朋友诉求（2026-08-27）→ memorial 014 grill（Q1 环境 / Q2 形态 / Q3 仓库 / Q4 token，D5–D13 授权定案）→ ADR-0029 → 本 PRD。
