# PRD — 审批动画及时可见（播放计划结构等价门槛）

**Status:** ready-for-agent

## 问题陈述

用户在 DSH Web GUI 里使用姜晓角色浮层时，当会话需要用户审批（工具授权 / 提问），角色**不立刻播放 permission（需大人首肯）动画**；整个等待期间画面可能一直卡在一段无关的过渡动作上；而**批准完成后**，permission 造型反而作为退场过渡的首帧出现了——用户看到的是「批完了才播要权限的动画」。

等待时间无论多长（远超动画本身时长）都可能出现，说明不是素材加载慢，而是播放推进被某种东西持续打断。

## 解决方案

把「会话状态机输出播放计划 → 屏幕上当前可见素材项」的推进决策收敛为一个可测的纯逻辑**播放游标**：只有当播放计划的**内容**（长度与各项身份）真正变化时才重置播放位置；计划内容不变时，无论上游产生多少次快照更新，入场过渡链都按素材真实时长连续推进，直到落入目标循环态。

效果：审批弹出后，permission 入场动画不再被后台事件打断，能完整播完并驻留循环态；批准后退场自然衔接；其他所有状态的切换、变体轮换、点击惊吓等既有体验不变。

## 用户故事

1. 作为 DSH Web GUI 用户，我想要会话弹出审批请求时姜晓尽快开始播放 permission 入场动画，以便我立刻意识到有事情需要我处理
2. 作为用户，我想要审批等待期间无论后台发生多少会话事件（投影更新、队列镜像、其他会话动静），permission 入场过渡都能完整播完并驻留循环态，以便我不会一直盯着无关的中间画面
3. 作为快速点击批准的用户，我想要批准后角色从 permission 自然退场回到工作呈现，以便动画叙事连贯不突兀
4. 作为长时间不处理审批的用户，我想要 permission 循环态稳定驻留不被挤掉，以便我过很久回来看仍能一眼识别「在等我」
5. 作为同时观察多个会话的用户，我想要任意状态的入场过渡都不被高频会话帧打断，以便每个状态变化都可读
6. 作为开启变体动作轮换的用户，我想要待机/工作变体照常轮换推进，以便本次修复不改变既有观感
7. 作为喜欢点击角色的用户，我想要点击惊吓（poke）序列照常播放与回落，以便本次修复不改变既有交互
8. 作为开启「减少动态效果」偏好的用户，我想要本修复不引入任何新的动画依赖，以便开关行为与之前完全一致
9. 作为开发者，我想要「计划进 → 可见项出」的推进决策是一个纯逻辑模块，以便不启动浏览器就能回归测试
10. 作为开发者，我想要计划等价判定有边界用例覆盖（同内容不同引用、长度变化、单项变化、空计划），以便门槛语义不会悄然漂移
11. 作为开发者，我想要设计会话中的两个仿真场景（等待期每秒一次无变化帧、零事件对照）固化为仓库内回归用例，以便该缺陷永不复发
12. 作为维护者，我想要会话 runtime 的事件通知语义保持不变，以便修复范围最小、不波及 UI 订阅契约

## 实现决策

- 采纳 ADR-0016 决策 D1：播放索引重置门槛为**播放计划结构等价**——新计划与上一计划长度相同且各项 `kind`/`url` 逐项相同 ⇒ 视为同一计划，沿用当前索引继续推进；否则归零重播。必须结构比较而非裸引用比较：显示层的 poke／摸鱼彩蛋／并行驻留分支每次都重建计划数组（新引用、同内容）。
- 新增唯一测试 seam：**播放游标纯逻辑模块**（本会话 prototype 仿真沉淀的接口形状，决策密集部分内联）：

  ```ts
  interface PlaybackCursor {
    /** 每次拿到新播放计划时调用；内容等价则沿用进度，否则归零。 */
    onPlan(plan: readonly PlaybackItem[]): void;
    /** 时间驱动：过渡段按素材真实时长推进到下一项；循环态驻留。 */
    tick(nowMs: number): void;
    /** 当前应渲染的项（索引钳制到末尾）。 */
    readonly current: PlaybackItem;
  }
  ```

- 角色浮层组件删除内联的索引状态与推进定时效应，只消费播放游标；过渡段时长解析沿用现有的 webp 动画时长解析（带缓存、失败回退 800ms）。
- 会话 runtime 的无条件通知语义保留；runtime 层「实质不变不通知」的去抖方案被否决（改动面大、需重新验证订阅通知契约、收益与 UI 侧门槛重复）。
- 新的渲染契约：播放计划的**内容**是推进的唯一身份。任何层想强制重播一段相同的计划，必须改变计划内容（例如加入 nonce 项），不能再依赖重建数组。
- 不修改素材、不修改显示仲裁顺序（紧急抢焦/poke/并行驻留的优先级不动）、不修改 SDK 与宿主行为。

## 测试决策

- 测试形态沿仓库先例：node 环境纯逻辑 vitest，注入虚拟时钟，参照会话 runtime 测试的「输入事件序列 + 时钟推进 → 断言输出」模式。
- 只测外部行为：对播放游标给「计划序列 + 时钟拍」，断言「当前可见项」；不测内部索引/缓存结构。
- 必测场景：
  - 等待期每秒注入一次内容相同的计划更新，持续 30s，permission 入场过渡链仍走完落到 permission 循环态（缺陷回归主场景，自 prototype 仿真固化）；
  - 对照组：零重复更新时，两段过渡按真实时长（各约 3.5s）推进，约 7s 落到 permission 循环态；
  - 同内容新引用不重置进度；任一项 `url`/`kind` 变化或长度变化则归零；空计划边界；
  - 批准后退场：计划切换后从新计划首段开始推进；
  - 变体轮换推进（url 变化）触发归零，不影响后续驻留。
- 仓库构建约束：改动后必须通过构建打包与发布前验收（`npm run build` + `npm run verify`）。

## 超出范围

- poke 惊吓序列遮蔽紧急态约 8 秒（特性 06 的 issue 09，另行实施）。
- 并行驻留全程遮蔽焦点会话自身紧急态（同上 issue 10）。
- 紧急态入场跳过过渡段直接 cross-fade 的「即达」增强（issue 11，缓议待人工决策）。
- 过渡段素材本身约 7 秒的串联时长（素材侧问题）。
- ADR-0014 审批等待时间启发式（runningCalls 卡住兜底进 permission/angry）的实现。
- SDK / 宿主侧的任何行为变更。
