# 气泡内容弹框：固定尺寸三列问答对照（去抖动 + 显示 LLM 回复）

Status: resolved

## 问题陈述

鼠标 hover 会话气泡浮现的「气泡内容弹框」（ADR-0031）现状有两处让用户难受：

1. **高度抖动**：弹框宽固定（280px）但高是 `maxHeight`（260px），盒子随内容伸缩。用户在左列切换不同问话（长短不一）时，弹框高度反复变化，浮层顶缘上下跳动，阅读体验被视觉抖动打断。
2. **只见问不见答**：弹框只罗列用户自己的问话（host 路由仅提取 `user/message`），看不到 LLM 对每条问话回了什么。想回顾某轮答案必须点进气泡跳进完整会话，弹框失去了「快速预览」的价值。

## 解决方案

把气泡内容弹框重排为**固定尺寸的三列问答对照浮层**：

- **尺寸恒定**（560×320，宽/高都用固定值而非最大值）：切换任何问话弹框都不再伸缩，抖动根除；某列内容放不下时列内独立滚动，整体框体不动。
- **三列**：
  - 左列 = 会话标题 + 竖排可滚动的**问话摘要行**列表（每行一条问话的截断摘要）。
  - 中列 = 当前选中问话的完整原文。
  - 右列 = 该问话配对的 LLM 回复全文（**问答案配对**，ADR-0032）。
- 左列选中态（默认最后一条 = 最新一轮）统一驱动中、右两列，hover/点击在既有语义内工作；因此「打开弹框即看到最近一轮问答」天然满足，无需额外操作就能看到 LLM 最新回复。

数据层新增把每条用户问话与其后的 LLM 最终回复配对，经既有 host 路由下发。

## 用户故事

1. 作为浏览会话气泡的用户，我希望 hover 气泡弹出的内容弹框大小始终固定，以便切换不同问话时浮层不会上下跳动晃眼。
2. 作为浏览会话气泡的用户，我希望弹框高度不随内容长短伸缩，以便弹框出现位置可预测、不打断阅读节奏。
3. 作为回顾对话的用户，我希望在弹框左列看到这个会话的全部问话摘要列表，以便快速定位到想重看的那一轮。
4. 作为回顾对话的用户，我希望左列问话摘要以竖排单行列表呈现（每条一行、过长省略），以便在窄列里从上到下扫读。
5. 作为回顾对话的用户，我希望问话很多时左列可以上下滚动而不是被折叠隐藏，以便任何一条问话都能被翻到。
6. 作为回顾对话的用户，我希望弹框打开时默认选中最后一条问话并自动滚到可见，以便落地即看最新一轮。
7. 作为回顾对话的用户，我希望 hover 左列任一摘要行时中列切换为该条问话的完整原文，以便读到当初自己问题的全文。
8. 作为回顾对话的用户，我希望 hover 某摘要行后即使移开鼠标选中仍保持（latch），以便把光标移到中/右列细读时内容不被切走。
9. 作为回顾对话的用户，我希望选中某问话时右列同步显示 LLM 对这一问的回复，以便问答对照、一次看全一轮。
10. 作为回顾对话的用户，我希望「最新一轮问答」在默认打开时就直接可见，以便无需点选即可看到 LLM 最新的回复。
11. 作为回顾对话的用户，我希望在弹框里读到 LLM 回复的完整内容（而非又一层摘要），以便判断当时答复的结论。
12. 作为阅读长回复的用户，我希望中列或右列内容超出时各自在列内滚动，以便长问答不被裁掉、整体框体尺寸不变。
13. 作为阅读的用户，我希望问话还没有对应回复时（如末轮仍在跑、被中断）右列显示「暂无回复」占位，以便明白是暂时没有答案而非加载出错。
14. 作为点击回顾的用户，我希望点击左列某问话摘要行仍像点击气泡一样跳转打开该会话，以便进入完整上下文继续。
15. 作为键盘使用者，我希望左列摘要行可聚焦、方向可达，以便不依赖鼠标也能浏览问答。
16. 作为使用深色/浅色主题的用户，我希望三列弹框在两套主题下都清晰可读，以便跟随系统观感。
17. 作为开启「减少动态效果」的用户，我希望弹框切换与出入无动画（instant），以便符合系统偏好。
18. 作为气泡位于屏幕边缘的用户，我希望弹框仍按视口自动翻转/钳制位置，以便三列加宽后也能完整落在可见区内。
19. 作为拖动角色浮层的用户，我希望 hover 弹框不触发整盒拖动，以便在弹框内正常移动光标操作。
20. 作为 hover 后移开的用户，我希望弹框按既有宽限期与淡出动画收起，以便不会突然消失、交互连贯。
21. 作为同一会话有新活动的用户，我希望下次 hover 看到更新后的问答，以便预览不会停留在旧快照。
22. 作为浏览超长会话列表的用户，我希望预览数据缓存有上限防无界增长，以便长会话场景不拖慢界面。
23. 作为运行极长单会话的用户，我希望问话与回复文本有长度护栏，以便单条超长内容不撑爆路由响应与弹框。

## 实现决策

- **布局方向（三列）**：弹框体由「竖排三段：标题 / 横排问话胶囊 / 详情区」改为「三列横排：左（标题+问话摘要行）/ 中（选中问话全文）/ 右（配对 LLM 回复）」。左列选中态统一驱动中、右两列。
- **固定几何（根治抖动）**：几何常量 `POPUP_WIDTH_PX` 由 280 调为 560；以新增固定高度常量 `POPUP_HEIGHT_PX=320` 替换原 `POPUP_MAX_HEIGHT_PX`，组件 inline style 注入固定 `height`（而非 `max-height`）；三列：左列固定 160px，中/右列各 `minmax(0,1fr)` 等分左列之外的剩余宽度（≈179px，160/200/200 是 560 三等分的粗略意图值，计入 padding/gap/边框后中右取等分）。视口定位纯函数按固定高度钳制，翻转/边距行为不变。
- **内容溢出策略**：弹框整体尺寸恒定；内容不足留白，超出时中列、右列、左列列表各自 `overflow-y: auto` 列内滚动。不再用「+N/收起」折叠胶囊（竖排滚动替代），故折叠相关纯函数路径（`foldCapsules` / `capsuleLayout` 的折叠态与 moreCount）在弹框渲染中退场——保留或删除由实施时按测试影响评估，不作为必须保留的行为。
- **选中/滚动**：默认选中最后一条问话并 `scrollIntoView`（垂直）滚到可见；hover→选中、latch 保持、点击→跳转、键盘 focus 语义均沿用现有实现，仅承载元素从胶囊改为列表行。
- **数据契约扩展（host）**：`/api/dsh-jx/session/<id>/messages` 响应由 `{title, prompts:[{seq,text}]}` 扩展为 `{title, prompts:[{seq,text,reply}]}`，`reply: string | null`。
- **问答案配对规则（host，ADR-0032）**：把 `collectUserMessages(events)` 扩展为逐问配对（如 `collectConversation(events)`）——对第 N 条真人问话，`reply` = 其后、下一条真人问话（`user/message` 且 `data.source.kind==='user'`）之前，最后一条**非空文本** `assistant/message` 的文本拼接；找不到则 `null`。
  - 关键不对称（宿主 `packages/core/session`）：`user/message` 文本在 `data.content[]`；`assistant/message` 文本在 `data.message.content[]`（`data.message.source.kind==='model'`）。
  - 跳过项：含 `tool-call` 块的中间 assistant 消息、`content.length===0` 的空消息、注入型 `user/message`（`source.kind!=='user'`）。
  - `seq` 全局单调，可顺序扫描配对；沿用现有 `MAX_USER_PROMPTS`、`MAX_PROMPT_TEXT_CHARS` 类护栏，回复文本另设长度上限护栏。
- **client 解析**：`PromptLike` / `SessionPreviewData` / `parsePreviewResponse` 增加 `reply`，防御性缺省——响应无 `reply` 字段或类型非法时回落 `null`（旧 host 响应/退化条目不致整体判失败）。
- **子智能体边界**：子智能体输出在独立子会话，父 `inspect().events` 仅通过 subagent 工具 `tool/result` 体现、不含其为 `assistant/message`；本弹框右列只反映父会话主 Agent 回复，不覆盖子智能体回复（记为已知边界）。
- **主题/动效/挂载约定不变**：继续消费语义别名 + `--jx-*` 轨（无颜色字面量、深浅双主题 L2 remap）、`prefers-reduced-motion` 全关动画、`createPortal` 挂 `document.body` + `position:fixed`、挂 `data-jx-interactive` 排除整盒拖动、底缘锚定与出入淡入淡出节奏保持。

## 测试决策

- **主 seam = host 配对纯函数**（`collectUserMessages → collectConversation`，纯逻辑，输入事件数组、输出 `{seq,text,reply}[]`）。只测外部行为：给定构造的事件序列，断言每条问话的 `reply` 是否配对到「其后下一条真人问话前、最后一条非空 assistant 文本」；覆盖正例与边界（无回复→null、空 content 跳过、tool-call 前言后仍有最终文本回复、注入型 user/message 不当作轮次边界、末轮 running 无回复、超长护栏截断、seq 顺序）。先例：`tests/host/session-messages-route.test.ts`。
- **次 seam = client 纯逻辑 `session-bubble-preview.ts`**：`parsePreviewResponse` 对新增 `reply` 字段的解析与防御回落（无字段/非法类型→null、整包形状异常→null）；固定几何常量下 `computePopupPlacement` 的钳制/翻转仍成立。先例：`packages/dsh-session-bubble/src/__tests__/session-bubble-preview.test.ts`。
- **DOM 三列渲染与 CSS 不单设新 seam**：由 `npm run build && npm run verify` 保证可构建发布，抖动是否根治、三列阅读性靠目视/尺寸断言（如可选）验证；不为纯样式新增脆弱测试。
- **路由级**：host 路由 handler 已有端到端测（inspect 失败 404、id 非法 400、GET-only），扩展响应含 `reply` 后回归该测仍绿。

## 超出范围

- 会话内精确定位到某条问话/回复的锚点跳转（留待官方开放定位接口）。
- 子智能体（subagent）子会话内问答的展示。
- 「+N/收起」折叠交互（被竖排滚动替代，不再维护其折叠态）。
- 弹框内对回复的再操作（复制、点赞、反馈等）。
- 详情窗（`SessionBubbleDetail`，工单 16 的书页卡片）——是另一浮层，本 spec 不涉及。
- 视口自适应响应式断点重排（弹框是瞬态浮层，尺寸钉死，不做移动端多断点）。
