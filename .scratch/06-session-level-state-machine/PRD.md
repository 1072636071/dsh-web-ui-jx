# PRD — 会话级状态机与表情体系（多会话适配 + 过渡动画完整性）

**Status**: resolved（11 张工单全部闭环；03 起各票经实施或被 ADR-0016 四态收敛演进承接，issue 11 经人工裁定不实施关闭——见各工单关闭记录）
**来源**: memorial 004（15 轮追问、16 项决策、2 项调查、ADR-0008/0009 已回写）
**创建**: 2026-08-19

## 问题陈述

角色浮层状态机是**模块级单例**：全局只有一个 currentState 与一个 playback，任何事件全局覆盖。多会话运行（用户并行打开多个会话，各自有独立的 thinking/replying/working 状态）时，各会话事件互相覆盖，浮层无法反映"谁在干什么"；且当前只跟随用户打开的单个会话，后台会话完全无感知。

另一缺陷：过渡段素材真实时长 3484/5494ms，而播放推进用 `setTimeout(800)`——过渡动画实际只播了开头约 12 帧（真实时长的 15–23%），末帧定格永不出现，"过渡动画完整"不成立。

此外，6 个中间态表情（shy-smile/shush/nod-smile/frown-wave/chin-rest/cheek-rest）素材齐备但无任何触发意图，实际播放不到；用户要求新增开心/生气/惊吓三个生活化表情，并贴合姜晓人设（古风贵族少女剑士、聪明冷冽、异时间线赛博大明的智能助手）。

## 解决方案

将状态机重构为**会话级**：每会话一个状态机实例（随宿主会话列表同步生命周期），浮层只渲染**焦点会话**的播放序列；焦点由**焦点仲裁**决定（当前打开会话最优先，error/permission 可紧急抢焦，事件消退即自动交还）。过渡段播放时长改为**加载期解析真实时长**，动画完整播出。表情体系扩展：现有 6 表情活化（permission 情绪化 + idle 随机点缀），新增 3 生活化表情（开心=完成、生气=等待 10s 未响应、惊吓=点击/拖动一次），配 6 个新素材与台词。

## 用户故事

### 多会话状态独立

1. 作为用户，我希望多个会话各自独立推进状态与播放序列，以便后台会话的进展不打断当前会话的画面。
2. 作为用户，我希望切回某个会话时，浮层直接显示该会话的当前状态，以便画面与"我正在看的会话"一致。
3. 作为用户，我希望会话结束后其状态保留在实例中，以便切回已结束会话仍看到正确画面（如 done）。
4. 作为用户，我希望会话从列表移除时其状态实例与订阅被彻底清理，以便长期使用无泄漏。
5. 作为用户，我希望新会话出现时自动创建状态跟踪，以便无需任何手动注册。

### 焦点仲裁

6. 作为用户，我希望浮层默认显示当前打开会话（`sessions.list.current`）的状态，以便所见即当前会话。
7. 作为用户，我希望切换打开会话时浮层跟随切换，以便始终反映当前会话。
8. 作为用户，我希望非焦点会话的普通事件（thinking/reading/replying/working/done/idle）不抢焦，以便浮层画面稳定不跳变。
9. 作为用户，我希望非焦点会话出错（hasError）时浮层紧急切过去提醒我，以便不遗漏错误。
10. 作为用户，我希望非焦点会话请求授权（pending）时浮层紧急切过去，以便及时处理授权。
11. 作为用户，我希望紧急事件解除后浮层自动交还焦点给我打开着的会话，以便无需手动切回。
12. 作为用户，我希望我手动点击会话气泡切换焦点后，紧急事件不覆盖我的手动选择，以便我的操作优先。
13. 作为用户，我希望焦点切换时画面以 150ms 淡入淡出过渡，以便不突兀生硬。

### 过渡动画完整性

14. 作为用户，我希望过渡段动画按真实时长完整播放，以便看到完整动作而非只播开头。
15. 作为用户，我希望过渡段末帧定格（536ms 收尾）被充分显示，以便动作收尾自然。
16. 作为用户，我希望通过 zip/目录导入的新素材自动适配播放时长，以便无需手动配置。
17. 作为用户，我希望素材时长解析失败时有兜底时长（800ms），以便播放链路不卡死。

### 生活化表情

18. 作为用户，我希望会话完成（done）时角色露出开心表情，以便获得完成的正反馈。
19. 作为用户，我希望授权/工具等待 10 秒未处理时角色露出生气表情，以便感知有待处理事项。
20. 作为用户，我希望点击角色时角色惊吓一次（播放完整段后自动回位），以便角色生动有趣。
21. 作为用户，我希望拖动角色时也有一次惊吓反应，以便拖动不显生硬。
22. 作为用户，我希望空闲时角色每 30–60 秒随机做一个小表情（微笑/托腮/捂嘴/点头等），以便角色不生硬呆板。
23. 作为用户，我希望 permission 场景角色经 nod-smile（点头）/ frown-wave（皱眉）过渡，以便情绪贴合授权语境。
24. 作为用户，我希望表情段播完自动回到当前循环态，以便不会卡在表情画面上。
25. 作为用户，我希望表情触发时弹出配套台词（若有填写），以便台词与表情一致。

### 台词与可访问性

26. 作为用户，我希望状态切换与表情触发时弹出符合姜晓人设的台词，以便角色有灵魂。
27. 作为用户，我希望 `prefers-reduced-motion` 下所有动画（过渡/表情/淡入淡出）关闭，以便无障碍。
28. 作为用户，我希望表情与过渡动画不拦截指针操作（表情播放期间可继续拖动/点击），以便不干扰使用。
29. 作为用户，我希望全部特效关闭时浮层行为与动画仍可用但不喧闹（表情属于角色动画、不受特效开关控制），以便极致性能模式不丢角色基础功能。

## 实现决策

1. **新纯逻辑模块（唯一 seam）**：`overlay-session-runtime` —— 封装会话容器（`Map<sessionId, 状态机实例>`）、差分推导接线、焦点仲裁、表情意图调度、playback 输出。对外暴露与现有状态机同构的订阅接口（getSnapshot/subscribe，useSyncExternalStore 兼容），渲染层只消费快照。纯逻辑、无 DOM、无 React。
2. **每会话推导复用**：现有差分推导器（`diffTarget`：error > permission > working > replying > thinking > done > idle，reading 由 thinking 超时推导）按会话接线，不再只跟 current。
3. **焦点仲裁状态**：normal（焦点 = 当前打开会话）↔ preempted（紧急抢焦：error/permission）；交还规则 = 紧急事件消退即交还，用户手动切焦（点击会话气泡）则焦点永久保留该选择，直到再次手动切换。焦点信号源 = `sessions.list.current`。
4. **跨会话切换不播状态机过渡**：焦点切换直接切到目标会话当前循环态，渲染层 img opacity 150ms 淡入淡出（CSS）；过渡段只存在于单一会话内部的状态演变。
5. **生命周期随 `list.ids`**：会话出现即注册实例 + 挂订阅，从 ids 移除即销毁并释放全部订阅。
6. **播放时长精确化**：素材加载期 ANMF 解析真实时长 → 动态填充过渡段 durationMs（失败回退 800ms）；解析结果按素材 URL 缓存。
7. **表情意图**：新增意图类型（happy/angry/shocked + idle 随机点缀调度）。生气阈值 = pending 进入后 10s 未响应（复用 1s tick 时间驱动先例）；惊吓 = pointerdown 触发一次「idle→表情→idle」播完即回，拖动中不重复；idle 随机点缀 30–60s 一次（6 现有 + 3 新增混池）；permission 进场经 nod-smile/frown-wave 情绪化。
8. **新素材（6 个）**：`transition-idle-happy/angry/shocked.webp` + `transition-happy/angry/shocked-idle.webp`，入 `assets/character/`（ADR-0003 契约），规格对齐现有（alpha 透明、67ms 帧、末帧 536ms 定格、画风一致）。素材未就绪时对应表情意图降级为普通过渡（不报错）。
9. **台词接入**：9 状态台词 + 3 表情台词从 `docs/character-lines.md` 台词场景表接入（文案由用户填写，实施时原样使用；留空场景不弹气泡）。
10. **渲染层最小改动**：CharacterOverlay 改订阅 runtime 快照（焦点会话 playback）+ 焦点切换淡入淡出 + pointerdown 惊吓意图；拖动与位置逻辑（ADR-0006）不动。

## 测试决策

- **只测外部行为**：输入（会话注册/注销、快照差分事件、焦点变化、意图）→ 断言输出（焦点会话、playback 序列、播放项时长、表情意图触发）。
- **被测模块**：`overlay-session-runtime`（唯一 seam，纯逻辑）。时间驱动（10s 生气、reading 超时、idle 点缀）通过注入时钟测试。
- **不测**：CharacterOverlay 的 React/DOM 渲染、CSS 过渡、webp 字节解析细节（解析器随运行时冒烟覆盖：已知帧数据 → 期望时长）。
- **先例**：`tests/client/state-machine.test.ts`（vitest node 环境，seam 2：输入意图断言 playback；36 过渡边、10 态互通、planSwitch 中转、宿主事件适配器均以该模式覆盖）。

## 超出范围

- 台词文案本身（用户手工填写 `docs/character-lines.md`，非代码交付）。
- 6 个新 webp 素材的制作（美术产出，规格见 `docs/animation-inventory.md`）。
- 宿主（deepseek-harness）侧任何改动。
- 会话气泡列（ADR-0007）重构——气泡列保持现状，仅消费同一 `sessions` 数据源。
- `docs/animation-inventory.md` 的后续补全（用户指示暂缓）。
- 中间态表情的循环态化（表情永不作 loop 终点，维持过渡段端点定位）。

## 补充说明

- 依赖已回写全局的 ADR-0008（会话级状态机 + 焦点仲裁 + 播放时长）与 ADR-0009（表情体系扩展），实施时以 ADR 为准。
- 建议实施顺序：runtime 纯逻辑模块（含测试）→ 渲染层接线 → 表情意图与素材降级 → 台词接入 → 全量验证（`npm run build` + `npm run verify`）。
- 素材未就绪期间表情功能通过降级路径先行验收（意图不崩溃、播放正常），素材到位后自动激活。
- 台词气泡与表情同时触发时：表情动画与台词气泡并行（气泡为独立层，两者不互斥）。
